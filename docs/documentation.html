Nexus AI — AI + SaaS Admin Dashboard

An admin dashboard template for AI SaaS products: agents, chat, prompts, token usage, usage-based billing, team management and integrations. Built with Next.js 14 (App Router), TypeScript, Tailwind CSS and Recharts.

This is a front-end template. It simulates an AI SaaS product with realistic mock data — there is no live backend. Every dataset lives in src/data/ and is typed against src/lib/types.ts, so connecting your API means changing one layer.

Installation

Unzip the package, then from the project root:

npm install
npm run dev

Open http://localhost:3000. The root path redirects to /dashboard.

Page pattern

Every module follows the same two-file shape:

// page.tsx — server component: metadata only
import type { Metadata } from "next";
import { AgentsView } from "./agents-view";

export const metadata: Metadata = { title: "AI Agents" };

export default function AgentsPage() {
  return <AgentsView />;
}
// agents-view.tsx — client component: all interactive state
"use client";
export function AgentsView() { /* filters, modals, handlers */ }
Server components cannot pass functions to client components. If you convert a view back to a server component, remove function props such as valueFormatter on the chart wrappers, or the production build will fail during static generation.

To add a module: copy a folder, add its route to src/components/layout/nav-config.ts, and add a data file in src/data/.

Colors & theming

Every color in the template is an HSL triple stored in a CSS custom property. Change the token and the whole dashboard — including charts — follows. Edit src/app/globals.css: 

:root {
  --background: 220 33% 98%;
  --foreground: 224 48% 12%;
  --primary: 258 89% 62%;     /* your brand color */
  --accent: 190 92% 42%;
  --success: 152 62% 40%;
  --warning: 36 94% 50%;
  --danger: 356 76% 54%;
  --radius: 0.75rem;          /* corner rounding, template-wide */

  --chart-1: 258 89% 62%;     /* chart series 1–5 */
  --chart-2: 190 92% 42%;
}
--primaryButtons, active nav, links, chart series 1
--accentSecondary highlights and chart series 2
--successPaid, connected, healthy states
--warningQuota alerts, pending states
--dangerErrors, overdue invoices, destructive actions

Fonts are set with --font-sans and --font-mono in the same block. To use a Google font, add next/font in src/app/layout.tsx and point these variables at the generated CSS variable.

Dark mode

Dark mode uses Tailwind's class strategy via next-themes. The provider is mounted in src/app/layout.tsx with defaultTheme="system". Override any token in the .dark block of globals.css. The theme switcher lives in the topbar and in /settings → Appearance.

Charts read the same CSS variables, so they re-render correctly on theme change with no JavaScript. If you hard-code a hex value in a chart, it will not follow the theme.

Internationalization

UI strings are collected in src/i18n/en.ts. Add a locale file with the same shape and register it: 

// src/i18n/index.ts
import { id } from "./id";
const dictionaries = { en, id };
export const locales = ["en", "id"] as const;

Because Dictionary is derived from the English file, TypeScript flags any missing key in a translation. For route-based locales, wrap the app in a [locale] segment or drop in next-intl.

Connecting an API

Each file in src/data/ exports plain typed objects. Replace an export with a fetch and await it in the page: 

// src/data/agents.ts
export async function getAgents(): Promise<Agent[]> {
  const res = await fetch(`${process.env.API_URL}/agents`, {
    headers: { Authorization: `Bearer ${process.env.API_TOKEN}` },
    next: { revalidate: 60 },
  });
  if (!res.ok) throw new Error("Failed to load agents");
  return res.json();
}

// src/app/(dashboard)/agents/page.tsx
export default async function AgentsPage() {
  const agents = await getAgents();
  return <AgentsView agents={agents} />;
}

A thrown error is caught by error.tsx; the loading.tsx skeleton shows while the request is in flight. Both already exist for the main modules.

The entity shapes in src/lib/types.ts mirror common LLM API and Stripe-style objects (Invoice, Subscription, PaymentMethod), so the mapping is usually one-to-one.

Authentication

The auth pages validate input and simulate the flow client-side. To make them real, add a provider such as NextAuth/Auth.js, Clerk or Supabase Auth, then:

  1. Replace the setTimeout in login-form.tsx with your sign-in call.
  2. Add a middleware.ts that redirects unauthenticated requests to /login.
  3. Swap currentUser in src/data/users.ts for the session user.
  4. Gate navigation entries against the role permissions in src/data/roles.ts.

Payments

Billing screens render Stripe-shaped objects. Card fields on /billing/payment-methods are a demo form — replace them with Stripe Elements or your provider's SDK so card data never reaches your server. Plan changes on /subscription should call your provider's subscription-update endpoint from a route handler.

Never place a live secret key in client code. Keep provider secrets in server-side environment variables and call them from route handlers or server actions.

Deployment

Node host

npm run build
npm run start

Works on Vercel, Netlify, Render, Fly.io, Docker or a plain VPS. Because all data is static, the build prerenders every route. Once you add live fetches, mark those routes dynamic or set a revalidate interval.

Static host

npm run build:static     # writes ./out

Emits plain HTML, CSS and JS in out/ for S3, Cloudflare Pages, Netlify Drop or any CDN. If the site is not served from the domain root, set the prefix so routes and assets resolve: 

NEXT_OUTPUT=export NEXT_BASE_PATH=/your-repo-name npm run build:static

GitHub Pages

.github/workflows/deploy-pages.yml lints, typechecks, exports the site with the repository name as the base path, switches Pages on through the API, and publishes it. Push to a branch listed under on.push.branches, or run it from the Actions tab. The site is served from https://<owner>.github.io/<repo>/.

GitHub Pages is available for private repositories only on a paid plan — a private repository on the free plan must be made public first. For a private repository, Vercel, Netlify and Cloudflare Pages all deploy this template on their free tiers. The deployment is fully static — there is no server — which suits this template since it has no backend.

Browser support

Latest two versions of Chrome, Firefox, Edge and Safari. Layouts are verified at 360px, 480px, 768px, 1280px and 1920px. The template honors prefers-reduced-motion and passes ESLint and TypeScript with zero warnings.

FAQ

Can I use this in a commercial product?

Yes, within the terms of your marketplace license. All bundled dependencies are MIT or ISC licensed.

Is there a plain HTML or React (Vite) version?

This package is the Next.js App Router build. The src/components tree is framework-agnostic React apart from next/link and next/navigation imports, so porting to Vite mostly means swapping those for your router.

Why is a form not saving?

Forms validate and show toasts but do not persist — there is no backend. See Connecting an API.

How do I remove a module?

Delete its folder under src/app/(dashboard)/, remove its entry from nav-config.ts, and delete the matching file in src/data/.

The dashboard widgets are in a strange order.

Widget order is saved per browser in localStorage under nexus:dashboard-widgets. Clear that key to reset.
